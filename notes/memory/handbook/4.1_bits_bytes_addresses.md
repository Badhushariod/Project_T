# Handbook page 1: Bits, bytes and addresses (Lesson 4.1)

*In my own words, from the teach-back on 2026-11-02.*

1. **Bit and byte:** A bit is the lowest memory representation, which can be
   either 0 or 1. 8 bits = 1 byte.
2. **LSB and MSB:** 0 is the LSB (worth 1) and 7 is the MSB (worth 128); bits
   are numbered right to left.
3. **Address and contents:** An address is like a house number, which is
   unique, and the contents are the data at the address.
4. **Why hex:** Binary is too big, decimal can't tell the bits, but hex is
   short and still tells the bits, because each hex digit = 1/2 byte (a
   nibble). Example: `0xFF = 0b11111111 = 255`.
5. **4 GB of names:** A 32-bit MCU has 32-bit addresses, `0x00000000` to
   `0xFFFFFFFF`, which is 2³² = 4 GB of names. Real SRAM is only 8 KB because
   memory costs money and chip space; the rest of the space is reserved or
   used for other things, and the fixed layout keeps every chip the same.

## Quick reference (from the lesson)

**What each bit is worth (one byte)**

```
bit number:   7    6    5    4    3    2    1    0
             MSB                                LSB
worth:       128   64   32   16   8    4    2    1
```
Binary → decimal: add up the worth of every bit that is 1.
`0b00100101` = 32 + 4 + 1 = 37.

**Sizes on Cortex-M**

| Name | Bits | Bytes | C type |
|---|---|---|---|
| nibble | 4 | ½ | (none) |
| byte | 8 | 1 | `uint8_t` |
| half-word | 16 | 2 | `uint16_t` |
| word | 32 | 4 | `uint32_t` |
| double-word | 64 | 8 | `uint64_t` |

**Nibble → hex digit**

```
0000 = 0    0100 = 4    1000 = 8    1100 = C
0001 = 1    0101 = 5    1001 = 9    1101 = D
0010 = 2    0110 = 6    1010 = A    1110 = E
0011 = 3    0111 = 7    1011 = B    1111 = F
```

**Address width → address space (N bits = 2ᴺ addresses)**

| Width | Range | Addresses |
|---|---|---|
| 8-bit | `0x00` – `0xFF` | 256 |
| 16-bit | `0x0000` – `0xFFFF` | 65,536 = 64 KB |
| 32-bit | `0x00000000` – `0xFFFFFFFF` | 4,294,967,296 = 4 GB |

**Sizes:** 1 KB = 1024 bytes, 1 MB = 1024 KB, 1 GB = 1024 MB.

## Watch out
- 0 doesn't always mean "off". On an active-low input, 0 means **pressed**.
  On `port_out`, 1 means LED **on**.
- Counting starts at 0: the 8th bit is bit 7.
- **word** = 32 bits on Cortex-M, but `WORD` = 16 bits in Windows/x86 documents.
- LSB/MSB can also mean least/most significant **byte** (Lesson 4.17).
- A value bigger than a byte uses several addresses in a row; its address is
  the **first** one. (A `uint16_t` at 500 uses 500 and 501.)
- `0x10` is **16**, not ten. Always write the `0x`.
- **KB** can mean 1000 (disks, networks) or 1024 (MCU datasheets).
  **KiB** always means 1024.
- `0xFFFFFFFF` is the **last** address, not the count. The count is 2³².
- On Cortex-M, the word and the address are both 32 bits: the same size,
  but different jobs (data size vs house-number size).
- A 32-bit MCU can **name** 4 GB; that doesn't mean it **has** 4 GB.
